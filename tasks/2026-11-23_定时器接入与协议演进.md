## M0 · 定时器接入（本阶段唯一要做的事）

### 目录（`src/timer/`，header-only，与 `lib/`、`src/mthread/` 一致）

| 文件 | 内容 |
|---|---|
| `timer_types.hpp` | `using Clock = std::chrono::steady_clock; using TimePoint = Clock::time_point;` 统一时钟口径 |
| `timer_queue.hpp` | 抽象接口：`add(id, tp)` / `cancel(id)` / `advance(now, cb)` |
| `scan_timer.hpp` | 最小实现：`unordered_map<int, TimePoint>`，每次 tick 全扫。**500 连接足够** |
| `heap_timer.hpp` | 小根堆 + 惰性删除（`cancel` 只打标记，`advance` 时弹掉） |
| `rbtree_timer.hpp` | `std::multimap<TimePoint,int>`，支持精确取消 |
| `wheel_timer.hpp` | 时间轮，固定槽数 + 圈数 |
| `idle_scanner.hpp` | 把 `timer_queue` 粘到 `Connection` 上：注册/刷新/扫描/踢人 |

一期只需 `timer_types.hpp` + `timer_queue.hpp` + `scan_timer.hpp` + `idle_scanner.hpp`
即可让 `06_timer.sh` 变绿；另外三个实现用来对照，接口相同，靠 `--timer=` 切换。

### 接线点（三处刷新 + 一处扫描）

```
handle_read(fd)      recv > 0                → conn->touch()
flush(conn,data,n)   ::send 返回 > 0          → conn->touch()
handle_write(fd)     wbuf_retrieve 之后       → conn->touch()
run_loop()           每 kWaitTimeOut(100ms)*N → scanner.advance(now) 收集超时 fd
                     → 放锁逐个 del_and_close
```

⚠️ 刷新点**必须包含 `send` 成功**。只在 `recv` 刷 → 只推不读的连接被误杀，
`06_timer.sh` 阶段 [2] 就是抓这个的。

### 验收

```bash
./test/suites/06_timer.sh                 # [1]die [2]alive [3]混合 [4]边界 全绿
./test/suites/06_timer.sh --server=reactor
./test/suites/06_timer.sh --timer=scan|heap|rbtree|wheel   # 四组合全绿
```

四条同时满足才算 M0 完成，缺一条都不算 —— `06_timer.sh` 的设计原则就是
「`close()` 一行能让连接消失，错误实现同样能让它消失」，必须正反两面都过。

## 关键陷阱备忘

### 陷阱 1：`ssize_t` 写成 `size_t`
上次小清理时把 `ssize_t n = ::recv(...)` 改成 `size_t n`，编译**静默通过**，
`-1` 变成 1.8e19，三个错误分支全部失效。
**凡可能返回 `-1` 的 syscall，返回值一律 `ssize_t`。**

### 陷阱 2：扫描时持锁删除
`del_and_close` 里有 `lock_guard(_mtx) _conns.erase(fd)`。如果扫描时本身就持有
`_mtx`，轻则死锁，重则遍历迭代器失效。必须「持锁只读收集 → 放锁 → 逐个删」。

### 陷阱 3：刷新点漏 `send`
只推不读（服务端持续推送）的连接，`recv` 永远不触发。少了 `flush` 里的
`touch()`，这类连接会在正常工作时被踢掉，而阶段 [1] 依然绿 —— 测不出来。
